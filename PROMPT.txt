我在一家做计量站改造的公司当仪表工程师。现场孔板流量计的选型、核算、复校，至今靠一张十几年前的 Excel，公式里混着几处手改的系数，一换取压方式或管道材质就没人敢打包票。这次想把它换成后端服务：选型时给流量求孔径，运行时给差压求流量，复校时拿流量和差压倒推开孔，三条路径都落回同一套标准方程上。

口径按 ISO 5167-2 的同心锐孔板。流出系数用 Reader-Harris/Gallagher 公式，含角接、法兰、D 与 D/2 三种取压方式各自的 L1、L2′ 项；可膨胀性系数按标准里的气体公式，液体取 1；质量流量 qm = C/√(1−β⁴)·ε·(π/4)d²·√(2ΔP·ρ1)。流出系数依赖雷诺数，雷诺数又依赖流量，所以给差压求流量本身是个隐式问题。管径和孔径按工作温度做热膨胀修正，管道与孔板材料各给线膨胀系数，参考温度 20 °C。适用范围照标准：D 在 50–1000 mm，β 在 0.1–0.75，ReD 下限随 β 变化。越界时照常算出结果，同时附超范围标志，并指明越界的是哪一条。

三种求解：正向，已知 D、d、ΔP 与流体物性求 qm；选型，已知 qm 和允许的最大差压求 d，求出的 β 落在适用范围外要说明；复校，已知 qm 与 ΔP 反求 d。每个响应带上迭代次数、最终残差、收敛时的 C 与 ε。任一种求解 50 次内不收敛就明确返回未收敛，附最后一步的状态，不许给出一个看着像答案的数。

我最看重三条路径彼此闭合。正向算出的 qm 拿去复校，得到的 d 与原孔径相对偏差小于 1e-9；选型求出的 d 再正向回算，qm 与目标偏差小于 1e-9；其它不变、差压加倍时，qm 之比应在 √2 附近，偏差只来自 C 与 ε 的变化，液体高雷诺数工况下与 √2 相差不超过 0.1%。此外：角接与法兰取压在同一工况下流出系数的差值，要能与 L1、L2′ 两项的贡献逐项对上；工作温度恰为 20 °C 时热膨胀修正退化为恒等；孔板与管道同材质时 β 不随温度变化。标准附录里的算例挑两到三个做成回归测试。

现场常用的表计要能落成具名档，档里记管道内径、孔板开孔、取压方式、两种材料、所测介质（液体给密度与粘度，气体给等熵指数、密度与粘度）。调用时可点名某档再覆盖个别字段，也可不建档直接传全部参数。档的增删改查要在重启后仍然保留。非法输入返回结构化错误，至少覆盖：差压非正、孔径不小于管径、密度或粘度非正、气体缺等熵指数、压比使 ε 超出公式有效域。

技术上用 Go 1.23 和 Gin，表计档存一个 SQLite 文件即可。标准方程、热膨胀修正、三类求解、适用范围检查、档存储、HTTP 层放在不同的包里，go test 覆盖上面的闭合关系与标准算例。交付一个以 golang:1.23-alpine 为构建阶段的多阶段 Dockerfile，运行时给 SQLite 文件挂一个卷，容器起来后就能直接调接口。
